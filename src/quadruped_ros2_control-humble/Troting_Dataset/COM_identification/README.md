# 本次质心辨识程序完全失败

记录日期：2026-10-23。记录范围：本目录保存的三套真机数据、此前终端日志，以及本轮离线调试。

**本次质心辨识程序完全失败。** 用户要求的是可以用于机器人标定的**机身质心**；本程序没有交付可信的机身质心结果。三维辨识失败后，改为只辨识 X、Y，仍未解决跨姿态结果矛盾的问题。下列数值仅作为失败证据和调试记录保存，不能作为已经完成的标定结果使用。

六段动作能够完成、CSV 能够保存、Python 能够运行、最小二乘能够输出数值，都不能据此宣称质心辨识成功。本次程序的采集和计算流程已经跑通，但辨识目标没有实现。

## 1. 用户要求与最终采用的计算口径

- 辨识对象为 trunk 机身本体，排除四条腿；不能把整机质心当作机身质心交付。
- 真机整机质量采用用户提供的近似称重值 **41.8 kg**，不再用力矩反算质量替代该输入。
- 本次 URDF 中非 trunk 部件质量合计 **18.01960159 kg**，因此计算采用机身质量 **23.78039841 kg**。这一拆分仍依赖模型中的其余部件质量。
- 用户已确认 CAN 力矩映射、换算准确；后续分析沿用这一前提，没有自动调整量程、符号、减速比或零偏。
- 最终目标只保留机身 X、Y；Z 不辨识、不验收，结果字段中的 Z 为 `null`。
- XY 版本在计算时将机身 Z 固定为 URDF 参考值 **−0.003836728 m**。这是一个固定假设，不是测得的质心高度；机身有倾角时，XY 仍依赖这一参考高度。
- 原来的运行命令、键盘按键和动作流程保留；默认安装位置的独立 Python 计算脚本已经同步为 XY 版本，不要求用户增加路径参数。

## 3. 为什么判定完全失败

### 3.1 同一机身在不同姿态下给出互相矛盾的 XY

使用最后一套真机数据、相同的 41.8 kg 整机质量和固定 Z 参考，将各正式姿态分别代入二维力矩方程，得到以下机身 XY。数值按该姿态平均数据离线计算并四舍五入，用于暴露姿态之间的矛盾，不是额外的标定结果。

| 姿态 | 单姿态机身 X mm | 单姿态机身 Y mm |
|---|---:|---:|
| reference | −34.622 | −6.176 |
| pitch_positive | −162.513 | −5.935 |
| roll_positive | +103.328 | +33.211 |
| pitch_negative | +98.006 | −37.951 |
| roll_negative | −102.662 | −40.464 |
| reference_repeat | −26.164 | +56.579 |

pitch 正、负两个姿态给出的 X 相差约 **260.52 mm**。一个刚性机身在 trunk 坐标中的质心不应随这些姿态发生这样的变化。在当前固定高度与反算模型下，数据无法由同一个机身 XY 同时解释。

最终报告中的 `X=−20.32 mm、Y=+0.076 mm` 是对这些互相矛盾的数据进行拟合后的折中。把它突出作为“质心结果”交给用户，容易造成误导，不能视作已完成标定。

前一套真机数据也存在相近的姿态相关变化：pitch 正、负分别给出 X 约 `−157.60 mm`、`+108.72 mm`。这表明问题具有可重复的系统性特征，不能仅凭“再多采一遍”解决。

### 3.2 反算合力没有满足采用质量的静力平衡

当前算法从关节力矩反算各腿足力，再检查合力与采用质量的重力是否平衡。最后一套数据中的结果如下。**这些力和力矩都是模型反算值，不是足底传感器实测值。**

| 姿态 | 合力平衡残差模长 N | 反算合力矩沿重力方向的分量 N·m |
|---|---:|---:|
| reference | 132.338492 | 2.529032 |
| pitch_positive | 79.776368 | 1.389596 |
| roll_positive | 52.500588 | 6.014193 |
| pitch_negative | 39.822014 | 2.862710 |
| roll_negative | 74.266519 | 1.914407 |
| reference_repeat | 76.898863 | 0.070394 |

在静态、无未建模外力/外力矩的假设下，应满足 `sum(f_i) + m*g_B = 0`。改变机身质心只能改变重力矩，无法消除上述合力残差。

同样，在这些假设下，重力矩沿重力方向的分量应为零；改变质心坐标也无法消除这个分量。因此，目前的问题不只是最小二乘求解精度，而是**输入数据与当前静力反算模型之间存在未被解释的不一致**。

### 3.3 取消 Z 求解后，XY 仍缺乏一致性

最后一套 XY 求解矩阵秩为 **2**，条件数约为 **1.002226**。二维矩阵本身并不病态，但力矩拟合 RMS 仍为 **13.966992 N·m**，回中一致性指标为 **36.021 mm**，留掉一个姿态重算时 XY 最大变化约为 **27.996 mm**。

因此，放弃 Z 解决了“不再交付异常高度”的问题，没有解决 XY 的可信度问题。单纯删掉质量检查或提高容差，只会改变通过标记，不会修正这些数值矛盾。

回中一致性指标是算法根据足力矩、模型和姿态修正后计算的指标，不是外部测量到的机身平移距离，也不是质心真值误差。

## 4. 已进行的调试记录

### 4.1 早期采集阶段：等待过久和中途终止

根据此前用户提供的终端日志，原流程使用 13 个姿态、至少 8 秒过渡、连续停稳后采集 10 秒。曾在 `pitch_positive` 等待持续停稳 30 秒后自动中止；也曾在正式采集过程中因运动质量判据触发中止。

这些中止是程序自身的状态机判据造成的。中止后，离线程序因 `completed=False` 拒绝接受整套参数。早期 `acquisition.json` 没有记录具体中止原因，离线输出只能显示“原因未记录”，调试信息不足。

后续调整记录：

1. 去掉以细小目标跟踪误差作为停稳依据的要求；固定的承重 PD 跟踪偏差不作为静止与否的判据。
2. 动作缩减为六段：原位、pitch 正、roll 正、pitch 负、roll 负、回中复测；删除升降和中间重复回中。
3. 默认过渡 3 秒、定时保持 1 秒、正式记录 2 秒，整套约 37～40 秒。
4. 运动质量超限改为记录与离线提示，不再因这类质量条件延长等待或中止动作；人工中止及严重异常保护保留。
5. 增加采集结束原因、写盘状态和运动质量累计计数。

这些修改解决了部分采集流程问题，但没有使质心标定成功。早期相关记录来自会话终端日志，所对应的全部原始采集目录并未保存在当前目录，不能假称已经逐帧复查。

## 5. 已知问题与尚未查明的根因

已确认的是：当前“反馈关节力矩 → 基于模型的足力反算 → 机身静力矩拟合”链路没有得到自洽的真实标定结果。质量固定、采集流程放开、增加输出和取消 Z 求解，都没有消除这一问题。

**尚未唯一定位最终根因。** 不能把调试推测写成已经证实的结论：

- 模型采用 foot 链接原点的点力接触；URDF 足底碰撞球半径为 20 mm，实际接触位置与可能的接触力矩尚未在该反算中完整验证。
- 已知部件质量、质心、实际关节零位和几何对反算结果的影响尚未完成独立实物验证。
- URDF 中存在 Fc；程序没有按微小 dq 的符号猜测静摩擦方向。现有证据没有证明静摩擦就是本次错误的唯一原因。Fc 尺度敏感性也不是已经验证的补偿或真实误差上界。
- 现有数据不能独立排除外部扶持、线缆作用或所有非静态效应。这里列的是观测缺口，不是在断言本次实验发生了这些情况。
- 没有独立足底载荷、真实机身平动和硬件采样年龄测量。不能用估计位置、速度很小来否定用户观察到的实际运动，也不能把反算接触力称为实测接触力。

在上述不一致未被解释、修正并验证前，不能靠放宽阈值把结果改成“通过”，也没有依据要求用户反复重复同一套真机动作来代替算法排查。
