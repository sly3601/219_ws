# 四足静态机身质心XY辨识

新增流程独立于腿部辨识、MPC、WBC和松弛优化。原文件仅增加FSM入口、状态枚举、安装项和必要的FixStand返回交接接口。
不自动修改URDF/xacro或控制参数；本次未编译、未进行真机验证。

## 使用

先按原流程稳定站到 **FixStand**，确认四足实际着地、不滑动，关闭其他运动键盘。
在机器人所在的ROS电脑、同一工作区环境运行：

```bash
ros2 run keyboard_input com_identification_keyboard
```

- `a`：一次按键进入并完成全部流程；`b`仅进入保持，不开始。
- `1`：中止并锁住**最后下发的关节目标**，保留原kp/kd和前馈；不失能、不自动回中。
- `h`：中止后人工请求缓慢回原FixStand目标；停稳后仍在辨识模式保持，不恢复采集。
- `x`或Ctrl+C：发送中止后退出键盘；键盘心跳丢失0.5秒也中止保持。
- 正常完成：按配置平滑返回原FixStand目标（默认3秒，包含微调偏置），定时保持1秒，CSV关闭后自动交还原FixStand模式。
- 回到FixStand后，用原键盘手动切换趴下，确认趴稳再断电；程序不会自动切PASSIVE、失能、趴下或断电。
- `1`/异常中止仍留在COM辨识状态原地保持，不自动回中/退出。每次控制器激活仅允许一套采集。
- 普通 `/control_input` 的1在此状态也只中止保持，与腿部辨识相同；其他FSM的原有1键行为不变。

**软件“保持”不是保证站稳的硬件急停。** 无足底传感器，程序不能证明四足仍接触地面，
也无法发现所有机械/驱动故障。保持最后目标避免清掉承重PD偏差，但不保证失稳后恢复。
只在与人员、核电站等关键设施隔离的测试区域验证，使用独立急停及不承重的防倒措施；
吊绳一旦承重、有人扶持或线缆拉拽，该段静态辨识无效。程序不操作实机启动或部署。

## 自动动作（6个正式段，默认约40秒）

初始站姿 → pitch+4° → roll+4° → pitch−4° → roll−4° → 回中复测。

删除升降段和中间反复回中，仅保留初始参考和最后一次回中复测。
升降不改变重力相对机身的方向；当前仅辨识机身X/Y，Z固定参考，不辨识、不验收。保留原六段动作用于跨姿态对照。
交错pitch/roll，避免直接从pitch正极值跨到负极值时出现更大的关节速度峰值。
±4°是相对初始名义目标的倾角变化，不保证实际机身角度精确跟踪；计算使用记录的IMU姿态。
默认每段正式采集2秒（约200帧），不再停稳后固定采10秒。样本可能相关，200帧不等于200次独立测量。
6段加5次姿态过渡以及最后返回/定时保持约37秒；不再因运动质量超限延长等待或中止整套。

6段采集结束后另有一次默认3秒的关节目标平滑恢复，回到进入前原FixStand的完整目标（含微调）。
恢复目标后按固定时间保持，再交还FSM；手动中止或严重反馈异常时仍保持，不自动切状态。
原FixStand仅新增从COM返回的专用enter分支：保留关节目标、kp/kd和前馈，不重置到实测角度，避免撤掉承重PD力矩。
其他来源进入FixStand的逻辑不变。交接时清除辨识期间遗留的状态命令，不自动执行趴下或失能。

四脚名义接触点始终固定；绕初始机身原点旋转，无平移XYZ、无yaw、无抬腿。
位置逆解只约束足端位置，不沿用FreeStand同时约束足端姿态的逆解。
每次五次多项式过渡默认3秒，定时保持1秒，再记录2秒；不再要求低速条件连续满足才开始记录。
运动质量参考为：全部关节速度≤0.015rad/s（绝对值）、陀螺模长<0.015rad/s，且反馈有限。
目标角度与反馈角度之间的固定承重PD偏差不参与停稳判断，不再要求进入0.10rad误差范围。
跟踪误差仅保留独立的过大偏差保护：超过0.30rad（约17.2°）中止保持，不用它判定静止。
质心计算使用实际反馈关节角，不用目标关节角代替实际腿姿。
不以0.003rad累计漂移、0.3°姿态漂移或加速度窗口作为在线门槛。
低速质量超限不重置计时、不延长等待、不中止动作；正式段照常记录并完成后续姿态。
CSV增加motion_quality_ok及本姿态motion_quality_bad_cycles，保留100Hz行之间发生的超限周期累计数。
CSV包含过渡/等待段以便排查，但质心计算只用phase=3的正式静态段。
累计漂移和加速度窗口仅作离线质量提示：仍计算候选参数，但出现异常时标记质量未通过；
速度质量超限仅离线标记，筛除相应帧后继续计算；可用帧低于80%也只标记，不因此拒绝候选计算。
完全没有可用帧、缺失姿态、损坏数据或人工/异常中止仍不能冒充完整有效辨识。
这些传感器检查不能排除全机匀速滑动、所有脚一起滑移或未被检测的传感器偏差，不能证明绝对静止。
最终回中复测段用于比较首尾重复性；减少回中次数也减少了对方向相关摩擦的诊断信息。
初始姿态来自FixStand当前指令，进入不重置到实测角度。

进入要求：当前FSM为FixStand、关节指令与配置stand_pos差小于0.015rad，关节速度<0.03rad/s、
陀螺模长<0.03rad/s、前馈/目标速度为零、kp/kd为有限正数、完整模型和键盘有效。
运行检查：单关节指令变化≤0.12rad/s、相对初始关节指令偏移≤0.20rad、关节限位留边、
逆解误差≤1μm、雅可比最小奇异值≥0.015m、实测关节速度≤0.4rad/s、
关节跟踪误差≤0.30rad（仅过大偏差保护）、反馈力矩≤80Nm、roll/pitch绝对值<8°且相对初始转角≤5°、
单周期IMU转角≤1°、控制实际周期≤20ms。异常锁存保持，不自动重试。
这些仅是保守的软件阈值，不是机器人稳定性证明。发生中止先看原因，不要盲目放宽。

新模块参数（在原控制器配置中需要时自行添加，运行中不动态改变）：

| ROS参数前缀 `com_identification.` | 默认 | 允许范围 |
|---|---:|---:|
| transition_s | 3 | 3～30s |
| settling_s | 1 | 1～30s |
| sample_s | 2 | 2～30s |
| tilt_deg | 4 | (0,4]° |
| output_directory | 源码工作区的Troting_Dataset/COM_identification | 文件目录 |

新流程不再使用height_m。若原配置显式指定transition_s/sample_s/tilt_deg，仍以配置值为准。

## 数据与自动计算

控制循环仅投递固定尺寸采样，约100Hz；独立线程写文件。实际时间以steady_ns为准。
默认写入源码工作区的 `Troting_Dataset/COM_identification/com_id_<时间>_<pid>/`。
当前Windows对应目录：

```text
D:\219_ws\219_ws\src\quadruped_ros2_control-humble\Troting_Dataset\COM_identification\com_id_<时间>_<pid>\
```

默认路径由本模块源码路径定位。ROS在Linux/虚拟机运行时，需让该工作区共享映射到上述Windows目录；
如果Linux使用另一份工作区，应把 `com_identification.output_directory` 配置为上述Windows目录的Linux挂载路径。
源码工作区目录不存在时拒绝初始化本模块，不会改存到临时目录。原有FSM仍可启动。

每次实验子目录包含：

- `robot_description.urdf`：实际模型快照，包含已辨识腿部参数。
- `metadata.json`：动作参数、FixStand配置目标、足端/坐标系名称。
- `samples.csv`：12关节q/dq/反馈tau/目标q/kp/kd，IMU四元数/角速度/加速度，阶段和真实时间。
- `acquisition.json`：CSV关闭后才生成；完整性/写盘失败标记及结束原因reason。中止数据不会冒充完整实验。

键盘收到目录通知后，用独立Python进程自动计算；计算不进入控制器线程。
需要Python≥3.10和NumPy。自动计算按键盘机器的本地路径访问，远程使用必须共享文件；
原命令和按键保持不变，默认安装位置的离线脚本已同步为XY版本，无需额外路径参数。键盘退出不删数据，可单独重算：

```bash
python3 <本目录>/process_com.py <工作区>/src/quadruped_ros2_control-humble/Troting_Dataset/COM_identification/com_id_<时间>_<pid>
# 有独立称得的整机质量时可增加 --mass-kg 41.0（示例值，不是本机标定值）
# 有实际踏步名义腿姿时可增加 --reference-q q.json（FR/FL/RR/RL共12个rad值，数组或{"q":[...]}）
```

自动生成 `results.json`、`report.md`、`debug.json`、`forces_estimated.csv`。
退出码0=计算成功且内部质量检查通过；2=计算成功、候选已生成但内部质量未通过；
3=数据被拒绝（中止、缺段、明显运动或无效数据等）；4=处理程序或文件读写异常。
键盘分别打印QUALITY_PASSED、QUALITY_FAILED、DATA_REJECTED、PROCESSING_ERROR；
进程未启动、异常信号和其他退出码另列，不再合并成“计算未通过或无法启动”。
即使退出码0，也不代表真实参数已获独立验证。

每项质量失败输出原因代码、姿态、实际值及阈值；累计角变化还输出关节名、起点/峰值角度、
正式段内时间及CSV sequence。逐姿态表区分原始帧数、离线选取帧数、足力有效帧数。
debug.json保存处理阶段、采集标记、脚本/CSV校验值、丢弃计数、模型参数对照和处理异常。
报告单列未建模静摩擦、足端原点接触假设与Gazebo effort来源；这些诊断不新增验收门槛，
诊断输出本身不修改反馈或补偿；当前候选求解和验收以XY为准。旧采集若没有保存中止原因，明确输出“未记录”，不猜测。
只重做输出、保留原采集报告时，可增加 `--output-directory /tmp/com_id_debug`；无需重新采集。

真机URDF硬件为hardware_sysu219/HardwareSysu219时，离线默认采用用户给定的近似整机质量41.8 kg，
减去非trunk模型质量后只拟合机身质心X/Y。显式--mass-kg仍可提供新的独立称重值；Gazebo不套用此默认。
CAN力矩映射按用户确认准确使用，不自动调整量程、减速比、符号或零偏。
力矩反算质量只作为诊断值，不作为真机质量输入。

新增body_wrench_debug.csv和body_joint_debug.csv，覆盖所有已有原始帧（含过渡、未入选帧）。
前者输出各腿位置/Jacobian/反算力/力矩、重力、力平衡残差、机身力矩拟合残差及入选标记；
后者输出每关节CAN力矩、q/dq/目标/kp/kd、P/D代理项、已知腿部重力项及求解右端。
debug.json新增完整机身拟合A/b矩阵、一阶矩、奇异值、每姿态力/力矩分解、时序和信号量化统计。
这些输出不新增采集中止条件，不补偿摩擦，不把反算接触力当作实测接触力。
现有接口无法独立观测足底载荷、外力、绝对平动或传感器采样年龄，不能保证单次数据解决所有物理问题。

## 算法与输出含义

静止时逐腿解 `J_i^T f_i = g_leg,i + B_i*dq_i - tau_feedback,i`。
g_leg包含全部已知腿部及附件重力；不把命令足力/命令力矩当测量，不另加一次电机PD。
静摩擦方向无法由静止时的速度确定，因此不以微小dq符号强行代入Fc；Ja静态不贡献。
估计的足力需满足四足正向承重、摩擦方向合理、雅可比有效等检查。

整机质量由合力重力方向分量求得，或使用独立输入质量；减去已知非trunk质量得到trunk质量。
每个姿态累计估计足力矩 `mu=sum(p_i×f_i)`，仅拟合trunk坐标的两个未知量X/Y。
Z默认固定为URDF中trunk惯性原点的Z，也可用 `--trunk-z-m <米>` 显式指定参考高度。
固定高度不是辨识结果；有倾角时X/Y依赖这个参考，不能把高度未知与水平投影混为一谈。
令 `R_t,p_t` 为trunk相对B的固定变换，`h_fixed=m_trunk*(p_t+R_t[:,2]*z_ref)`，则拟合：
`skew(g_B)*R_t[:,:2]*h_xy = mu-skew(g_B)*h_other-skew(g_B)*h_fixed`。
使用每帧重力矩的平均值；每姿态权重相同。求解矩阵只有两列，不再求异常Z。

关键结果：

- `trunk_com_xy_link_m`：机身质心 `[x,y]`，单位米，trunk坐标，排除四条腿。
- `trunk_com_link_m`、`trunk_com_B_m`：兼容字段为 `[x,y,null]`，Z没有辨识值。
- `z_policy`：固定高度参考、来源及依赖说明；不会把参考高度作为实测结果输出。
- `xy_quality_checks_passed`：XY质量检查；`xyz_quality_checks_passed`恒为false，三维未辨识。
- 整机质心兼容字段同样保留XY、Z为null，依赖已知部件模型和固定高度参考。
- `fixstand_projection_level_frame_xy_m`：足力反算的水平投影；倾斜时与trunk坐标X/Y不同。

FixStand和trot的实际腿姿不同，其整机质心就不同，不能自动称二者相同。
不辨识惯性矩阵，不使用有偏差的估计机身XYZ/速度，不把估计足力称为实测。

XY辨识检查二维矩阵秩（要求2）、条件数、跨姿态力矩残差、质量一致性、回中重复性、留一姿态XY变化。
删除Z坐标大小、Z留一变化和Z敏感性验收。Fc敏感性只报告XY，仍不是置信区间或补偿。
保留与XY可靠性有关的诊断，质量不足时仍输出候选并标记，不自动改模型或扩大动作。

离线程序按metadata.json中的姿态名称识别回中段，兼容新6段/2秒和旧13段/10秒数据；
不会把pitch/roll正式段当成回中段，也不会把缺失或中止的旧实验当作完整实验。
