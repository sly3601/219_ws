# 左前腿参数辨识实验与源数据采集

本目录说明专用 FSM、轨迹和 CSV 采集接口。运动学、方向、零位以及硬件驱动均沿用原工程。
`hardwares/` 和所有 xacro 不作修改。没有增加电机使能/失能参数，也没有修改正常硬件启动过程。

## Gazebo 悬空辨识场景

仿真辨识使用独立的启动文件：

```bash
ros2 launch sysu219_guide_controller gazebo_leg_identification.launch.py
```

它从原 `gazebo.launch.py` 复制，仅切换为无地面的 `leg_identification.world`，
并通过 xacro 已有的 `DEBUG=true` 开关启用 `world -> base` 固定关节，悬挂机身。
重力、腿部活动关节、控制器配置和主控制算法沿用原工程；不是将整台模型设为静态。
默认生成高度仍为 0.65 m，可用 `height:=...` 调整。

这个 launch 只布置仿真实验环境，不发送辨识指令，不启动辨识动作：
控制器依然从 `PASSIVE` 启动。另开终端运行下方专用键盘，按 `b` 进入辨识状态，
再用 `w/e/r/t/y/u/a` 选择测试，程序自动从当前姿态缓慢归位、确认到位后正式开始，`1` 急停。
也可先按 `q` 只做归位准备，不开始测试。悬挂机身时的自然下垂姿态不要求满足小幅激励窗口。

原 `gazebo.launch.py`、真机 launch、xacro、硬件驱动和主控制回路均不因这个场景而修改；
不增加场景专用的控制或保护逻辑。新 launch 和 world 由现有 launch 目录安装规则包含。

## 使用

由用户自行完成编译。按原来的方式启动真机工程，保持初始 `PASSIVE`。
在另一个交互式终端运行：

```bash
ros2 run keyboard_input leg_identification_keyboard
```

机身和其余三条腿由实验者机械固定，左前腿悬空、无足端接触。
不需要同时运行原键盘。此专用节点在辨识状态之外只允许请求入口，不执行任何辨识动作。

| 按键 | 行为 |
| --- | --- |
| `b` | 请求从 PASSIVE 进入腿部参数辨识；从其他状态发出则丢弃 |
| `q` | 仅归位准备或中止后恢复：保留已有增益，再平滑到辨识中心，不启动测试 |
| `w` | 三个姿态静态保持，各 15 秒 |
| `e` | 髋关节耸肩侧往复20秒，0～37°（约0～0.645772 rad） |
| `r` | 大腿关节运动20秒，中心0.5135、幅值±0.80 rad |
| `t` | 小腿关节运动20秒，中心−1.605、幅值±0.48 rad |
| `y` | 三关节联合多频运动，40 秒 × 3 次 |
| `u` | 独立验证轨迹，40 秒 × 2 次 |
| `a` | 顺序完成静态、三个单关节、联合多频、独立验证全部实验 |
| `h` | 中止当前动作，平滑回到中心保持 |
| `1` | 急停：中止测试，锁存当前位置、速度目标置零，保留当前增益；不失能、不自动恢复 |
| `?` | 终端帮助 |
| `x` / Ctrl+C | 先发急停，再退出键盘；辨识 FSM 保持锁定 |

其余数字键不执行动作。所有操作提示显示在**专用辨识键盘所在终端**。每项测试及每次重复均显示：

```text
髋关节测试（第1/1次）：开始准备，从当前位置缓慢移动到测试起点 [0, 0.5135, -1.605] rad。
髋关节测试（第1/1次）：准备完成，实测到位和低速条件已连续满足0.5秒。
髋关节测试（第1/1次）：正式开始，动作段20秒，正在记录250 Hz源数据。
髋关节测试（第1/1次）：本次测试完成，等待CSV写入确认。
髋关节测试（第1/1次），完成：数据记录完成，已写入并刷新CSV：.../samples.csv；正式段样本序号 [...]。
```

测试键自带准备阶段，不要求先手动把腿摆到起点，也不强制先按 `q`。
`q` 或 `h` 返回中心后保持，不自动开始测试。键盘的“已发送”仅表示发送请求，
以随后收到的准备、开始、完成消息为准。急停或中途换动作时显示“中止”，不会报测试完成；
已采集的数据保留并确认对应文件和样本序号。全套测试完成后会明确提示并缓慢回到中心保持。
实测位置/速度未满足准备到位条件时继续保持目标，每2秒显示误差与速度，不直接宣布正式开始。
键盘连接中断超过2秒会中止测试并保持当前位置，不清零增益。
增益渐入期间不接受新的动作，只接受急停；其余动作切换均先检查并执行连续过渡。
普通 `/control_input` 的其他模式指令在此状态内不引起 FSM 切换；其 `command=1` 仍可急停。
退出此 FSM 需要结束/重启控制器，键盘不提供回到正常行走状态的入口。

进入时全部关节的增益和前馈先清零。之后仅左前腿写入非零控制增益，其余九个关节持续
`kp=kd=tau_ff=0`，位置目标跟随所读位置、速度目标为零。这是状态内控制输出约束，
没有发送新增硬件禁用命令，也不等同于物理锁止或断电。
开始驱动后，普通异常、过渡失败、记录器故障和按键1均不清零左前腿增益。
中止时只锁存一次实测位置并保持，后续不追随反馈重新捕获目标；位置反馈非有限时保留最后有限位置指令。
恢复准备时增益从保留值向正常值渐入，不先降到零。按键退出后，只要控制器仍运行，就继续保持。

## 动作参数

辨识专用中心为用户确认的 `[0.0, 0.5135, -1.605] rad`，定义于 `Trajectory.h`。
髋0用于准备和回中；大腿、小腿取当前硬件/URDF限位交集的中点。
这项设置不修改原 `stand_pos` 或 FixedStand。增益仍复用 `stand_kp/stand_kd`，默认260 / 3.8。
初次准备从实测位置开始，用1.5秒渐入增益，再用4秒五次多项式缓慢过渡到测试起点。
准备完成的位置误差仍为 `[0.03, 0.12, 0.12] rad`、速度仍为
`[0.0075, 0.03, 0.03] rad/s`，连续保持0.5秒，不随放大的激励幅值放宽。
这些是实验准备的到位判据，不是额外的初始姿态限制，也不是硬件额定范围。
辨识算法使用实测 q/dq，不要求每次实测起点完全相同；设定起点用于重复实验与连续启动轨迹。

| 项目 | 髋 | 大腿 | 小腿 |
| --- | --- | --- | --- |
| 辨识参考中心 / rad | 0 | 0.5135 | −1.605 |
| 正式目标范围 / rad | 0～0.645772（37°） | −0.2865～1.3135 | −2.085～−1.125 |
| 激励量 / rad | 从0向正侧最大0.645772 | 中心±0.80 | 中心±0.48 |
| 静态姿态偏移 / rad | 0、+0.322886、+0.645772 | 0、+0.533333、−0.533333 | 0、−0.32、+0.32 |
| 目标速度保护 / rad/s | 0.5 | 2.0 | 2.0 |
| 目标加速度保护 / rad/s² | 4.0 | 15.0 | 15.0 |

用户搭建的平台在溜肩侧约5°处有干涉，因此本轮髋轨迹只使用 **0～37°耸肩侧**，
不把负向5°当成可达到的测试端点。方向依据为URDF中左前髋绕+X旋转、大腿关节位于其+Y侧，
以及已有趴姿中左前髋的正角；在新辨识中心，髋+5°使足端相对髋轴升高约12.3 mm，−5°降低约9.4 mm。
0仍是准备/回中位置，正式髋运动不再关于0对称：使用平滑包络乘以带正偏置的正弦/多频波，
即 `e(t) * A/2 * (1+s(t))`，其中 `s(t)` 在[−1,1]内。往复速度仍包含正、负方向，
起止目标位置均为0，目标速度和加速度也为0。
正式激励和正常动作切换的髋目标均检查在[0,0.645772] rad内；初次归位仍从实测位置出发，
使用既有硬件与URDF关节限位的交集，不要求初始姿态已经在测试区间内。
平台几何不在当前URDF或无地面Gazebo场景中，以上为根据用户场地信息设置的关节指令约束。
初始实测角度超出既有限位不超过约20°时允许准备，初始目标投影到合法指令范围内，CSV反馈不裁剪。
正式目标范围仍按表中参数规划，轻微实测越界或跟踪偏差不直接中止测试。
明显越界、非有限反馈或模型限位冲突会中止并说明原因；已驱动的左前腿继续保持，不失能。
动态动作使用原时间轴，时间倍率为1：单关节频率为 `0.5 Hz`；
联合多频为 `[0.3,0.6,1.2] Hz`，权重仍为 `[0.5,0.3,0.2]`。
验证频率为 `[0.4,0.8,1.1] Hz`，第二次再加 `0.05 Hz` 并改变相位。
大腿、小腿使用围绕各自中心的波形；髋在相同多频信号上加偏置后只走耸肩侧。
运动段首尾使用2秒C2包络，位置、速度、加速度使用同一时间尺度，
保留原目标速度、加速度和跟踪误差阈值，不通过提高阈值来容纳放大后的动作。
动作切换沿用原来的连续过渡：依次检查4秒、2秒、1秒候选，使用满足位置、速度、
加速度阈值的最慢方案；没有合格方案则中止流程并保持当前位置和增益。

全套正式动作段共305秒（静态45秒、单关节60秒、联合120秒、验证80秒），过渡和准备时间另计。
是否具有足够辨识激励，需要在后续阶段
根据采集数据的回归矩阵评估，不能从动作时长或样本数量直接保证。

关节范围取运行时 URDF 与真机接口既有限位的交集，正式激励目标再留0.1 rad余量；
初次归位不套用这项激励余量和髋激励窗口。
真机位置限位只读抄录于 `Trajectory.h`，来源为 `HardwareSysu219.cpp::on_init`：

| 关节 | 真机下限 / rad | 真机上限 / rad |
| --- | --- | --- |
| hip | −0.638 | 0.748 |
| thigh | −0.623 | 1.65 |
| calf | −2.322 | −0.672 |

不改变这些源文件。未来若原工程调整了真机限位，应同步核对辨识目录中的只读副本。
运动异常采用宽松判据：实测角度超出硬件/URDF限位交集约20°，或实测角速度超过10 rad/s。
这是辨识模块的异常阈值，不改变原硬件指令限位；约20°余量不是新的激励目标范围。
跟踪误差、80 N·m反馈力矩和20 ms控制周期抖动不再单独中止动作；源数据仍原样记录。
非有限反馈、记录器故障、键盘离线或运行期间URDF改变也会中止实验并保留增益、保持位置。
更换URDF后需重启控制器，以新模型开启新记录。以上行为只由辨识模块实现，不修改底层保护。

## CSV 和时钟

进入辨识状态即开始一个记录会话，默认保存于：

```text
/tmp/dynamics_identification/leg_id_<系统微秒>_<进程号>/
  samples.csv
  metadata.json
  robot_description.urdf
```

目录在专用辨识键盘终端显示。可用控制器参数 `leg_identification.output_directory` 改变输出根目录。
结束控制器会排空队列、刷新 CSV，并更新元信息的 `closed_cleanly`。
元信息在实验中也每秒更新；每秒刷新 CSV，控制循环不进行文件操作。
每次正式段结束或中止后，后台会额外确认该段末个样本已写入，刷新CSV与元信息，
再向键盘报告数据记录完成及样本序号；这不关闭记录会话，不把中止段标记为完整测试。
4096 项预分配单生产者/单消费者队列在满时明确报错并停止动作，不覆盖未保存数据。

采样按单调时钟的 4 ms 时间格调度，每格最多采集一个现有接口快照。
错过的时间格不补造数据；控制器实际更新较慢时如实降低有效记录频率。
每一行的位置、速度、估计力矩均来自同次控制调用可见的三个关节状态接口。

- `time_s`：从首个样本开始的单调时间，秒；后续滤波/求导使用此时间轴。
- `steady_ns`：`std::chrono::steady_clock` 快照时间，纳秒。
- `system_ns`：`std::chrono::system_clock` 日历时间，便于与现有 Trotting 日志对照。
- `ros_ns`、`period_s`：控制器传入的 ROS 时间与实际周期。
- `dt_s`：两行实际快照时间间隔；`sequence` 为采集样本序号。
- `action/phase/trial/phase_time_s`：动作、阶段、从 0 开始的试验编号及当前阶段时间。
- `phase=5` 是等待实测到位；`phase=4` 才是正式段。阶段0～4原编号保留。
- `FL_*_q/dq/tau`：已有方向/零位映射后的源位置、源速度、反馈估计力矩，单位 rad、rad/s、N·m。
- `FL_*_q_cmd/dq_cmd/tau_ff/kp/kd`：本周期控制接口目标，尚未经过已有硬件 write 限幅/协议量化。
- `imu_*`：已有接口的原始四元数 wxyz、角速度、线加速度；缺失/非有限值明确标记。
- `flags`：1=未驱动或中止保持，2=关节反馈非有限，4=IMU缺失/非有限，8=记录间隔不在 2～6 ms。
- `phase=6`：中止后保持当前位置，增益保留；与未驱动的 `phase=0` 区分，不作为正式实验段。
- `repeated_feedback`：三个关节的 q/dq/tau 全部与上一行完全相同。

没有增加驱动接收时间或反馈序号，故 `steady_ns` **是控制器快照时间，不是电机测量/接收时间**。
完全重复的数值也可能来自静止和量化；不能据此断定 CAN 丢帧，无法声称三个电机硬件同步采样。
这项限制在元信息中明确记录。250 Hz 指采集调度，不伪装成经过验证的 CAN 新反馈频率。
反馈力矩是原有估计值，不是独立力矩传感器测量，也不以同帧控制目标代替反馈。

CSV 不滤波，不计算测量加速度。轨迹内部用于平滑/保护的解析目标加速度不作为实测加速度保存。
训练/验证只提取 `phase=4`；`action=6` 为独立验证，其余正式运动段用于训练或静态辅助分析。
过渡、准备、停止和中心保持保留在源文件中，通过阶段字段区分。

纯数据质量检查（仅 Python 标准库，可复制至 Windows 使用；不滤波、不修改 CSV）：

```bash
python3 inspect_recording.py /tmp/dynamics_identification/leg_id_<系统微秒>_<进程号>
```

源码分工：`StateLegIdentification` 管理状态/动作与现有接口，`Trajectory.h` 定义轨迹，
`CsvRecorder` 负责后台源数据保存，`LegIdentificationKeyboard.cpp` 负责交互。
辨识状态的提示先进入预分配队列，由100 ms非实时定时器发布到 `/leg_identification/feedback`，
再由键盘节点显示；控制周期内不格式化提示、不打印、不等待键盘。记录器提示也由该定时器转发，
记录线程与控制线程各自独立。退出整个 ROS 进程时末条提示可能来不及送达，最终统计以 metadata.json 为准。
现有控制器只接入状态注册、PASSIVE 入口和停用清理，已有行走算法、固定姿态与硬件层不变。
