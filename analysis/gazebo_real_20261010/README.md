# Gazebo 与真机原地踏步日志对比

分析日期：2026-10-10。没有修改控制器、Gazebo 参数或真机配置，也没有启动实验。

## 数据身份与可比性

- `5121` 组三份：ROS 时间为 22.764–37.952 s，系统时间是 Unix 时间戳；据此推断是 Gazebo。
- `6695` 组三份：ROS 时间接近系统时间，且力矩反馈明显离散量化；据此推断是真机。这也符合用户描述的真机表现更好，但身份依据是时钟和反馈特征。
- 每组三份的 cycle 连续递增但窗口之间有缺口，是同一进程运行的不同窗口，不能当作三次独立重复实验。
- 两组 `v_ref` 三轴均为零，属于原地踏步。目标高度约 0.392 / 0.390 m，记录的支撑增益 0 / 4.5、摆动增益 160 / 3.8 一致。不能仅凭这些字段确认采集时全部软件、步态参数和环境都相同。
- 定量主比较使用两组第一份的 cycle 500–2500，即进入记录后 2–10 s，共各 2001 帧。后续窗口用于确认变化持续存在。时序图按各组起始 ROS 时间归零；两组步态绝对相位未对齐，不应用逐点相减评价误差。

关节速度一致性以相邻两帧反馈速度平均值，对比角度增量 / 实际 ROS 时间间隔；只使用连续 cycle 和有效时间间隔。

后两个窗口的估计高度平均偏差：仿真 −6.05 / −6.49 cm，真机 −2.03 / −2.47 cm。真机也有缓慢下降，但仿真幅度明显更大。

这些结果说明：仿真摆动腿跟踪更精确，整机表现却更差；单纯增加仿真 PD 增益缺少依据。日志中没有看到仿真速度反馈的明显倍率错误，也没有看到普遍的 100 Nm 饱和。

真机 `acc_G.z` 标准差反而更大（8.68 vs 1.91 m/s²），因此不能根据机身摇晃就认定仿真落脚冲击更强，也不应把“加大接触阻尼”当作已证实的修复。IMU 带宽、噪声、安装位置和滤波都可能影响这个指标。

## 日志量的含义与因果边界

根据当前日志代码：

- `p`、`v`、`feet_G`、`feet_v_G` 来自估计器，不是 Gazebo 真值。机身高度曲线下降不能直接证明物理机身下降了同样的距离。
- `contact` 是步态发生器的计划支撑状态，不是实际足地接触检测。
- `ground_force_P` / `force_sum` 是 MPC 规划力，不是实测反力。两组首份比较窗口的规划垂向力均值约 382.7 / 396.7 N，但不能据此认定仿真实际少了 14 N 支撑。
- 真机 `tau_feedback` 来自电机反馈估算，Gazebo effort 接口的来源和语义不同；两者都不能直接作为实际足底力。
- `tau_mit_est` 是接口位置、速度、增益和前馈力矩算出的总力矩，尚未考虑下游限幅、采样更新、量化和电机内部反馈。
- `touchdown_fz_proxy` 是由力矩反解的代理量，未扣除腿惯性、重力和反馈延迟，不能当作真实接触力。
- `q_raw`、`qd_raw` 是限幅前的逆运动学目标，**不是原始传感器反馈**。实际状态使用 `q`、`qd`。

## 当前代码与模型审计

以下是当前工作区配置的事实；不能由此反推 10 月 7 日采集时加载的二进制及全部参数必然相同。

1. Gazebo 上层控制 250 Hz、`leg_pd_controller` 500 Hz；后者计算 MIT PD 总力矩，并配置 `torque_response_time=0.004 s` 一阶响应。配置注释也明确它是尚未辨识的假设。真机把 MIT 指令发到电机，PD 在电机端执行，两条链路不等价。
2. GazeboEncoderSystem 用角度差分 / 仿真时间间隔替换 velocity 接口；上层估计器与仿真电机 PD 使用这条速度。真机当前硬件读取电机反馈速度。不能为了曲线相似随意放大速度或加滤波。
3. 用本机 `xacro` 展开并执行 `gz sdf -p` 验证了当前模型：总质量 40.500972 kg；四足球形 collision 半径 0.02 m；足端接触 kp=1e6、kd=1；mu=mu2=0.6；关节 damping=friction=0.1。当前 `kp value=...` 写法确实被本机转换器解析，未发现该参数不生效。
4. 足端通过 fixed joint 合并到 calf，转换器报告 calf/foot 摩擦参数覆盖提示；最终四足碰撞体的摩擦值是 0.6。后续必须检查实际 collision 参数，不能只看 foot link 名称。
5. 足端 visual 半径 0.01 m，collision 半径 0.02 m。估计器把运动学足端原点的高度观测设为零；球心与真实接触点有半径偏移，应在仿真真值比较时统一定义。2 cm 球半径本身不能解释随时间增长到 6–8 cm 的高度误差。
6. MPC 当前质量 40.5 kg、惯量 diag(0.624, 2.683, 2.934)、COM 偏移零、约束摩擦系数 0.35。规划摩擦系数低于物理摩擦系数不自动构成错误，它可以是保守约束，不应直接令两者相等。
7. 当前 StateTrotting 没有调用 WbcController 或 MpcWbcRelaxation；这两个 cpp 也不在当前主控制库的 CMake 源文件列表中。现有日志先按 MPC + 雅可比力矩 + 关节 MIT PD 链路分析，而不能归因于这两个新模块。
8. 当前控制器 Gazebo launch 没有显式传入 world 参数，而是调用 gazebo_ros 的 launch 默认值。修改仓库 `gz_quadruped_playground/worlds/default.sdf` 未必影响这个入口；需要保存实际启动命令、实际世界文件和运行时 physics 配置。

## 第一优先级：区分真实运动误差与估计误差

下一次 Gazebo 采集同步保留 trotting_debug 和现有诊断插件输出的 `/tmp/physics_debug_*.csv`。当前诊断插件已能记录机身真值、质量加权 COM、关节真速度、足球真位置 / 速度及接触信息；是否构建加载、是否启用 Csv_DebugMode 应按启动输出确认。

按仿真时间对齐，至少比较：

- `p_z` 与 **body/base 原点**真值高度。不要把估计器 base 原点直接与全机器人真实 COM 比较。
- 估计机身速度与 base 真速度；IMU 姿态与 base 真姿态，并统一 IMU 安装变换。
- 计划 contact 与实际 foot_contacts / contact_force。检查诊断记录的 contact_available 和 contact_s，防止把缺失或过期接触信息当作零接触。
- 计划支撑期间的真实足端切向运动。球心可以因滚动移动，球心移动不能直接等同于接触点滑动；应结合碰撞点及刚体点速度判断滑移。
- 计划触地 / 实际触地时间差、落脚垂向速度、离地后的残余反力、双支撑 / 四支撑时长。

若真实高度稳定而估计高度下降，应首先排查接触假设、IMU 处理与运动学观测；若两者一起下降，才把真实支撑和执行器动力学作为主要方向。若下降或摇晃集中在接触切换，优先处理落脚时序和接触模型。

## 第二优先级：辨识 Gazebo 电机与反馈链路

将反馈力矩与 MIT 接口估算按 0–5 个周期平移比较，六份日志都显示仿真最佳对齐约 1 帧、真机约 3 帧（名义 4 / 12 ms）。这是链路时序线索，**不是辨识得到的电机时间常数**；读取先于写入、通信延迟、反馈滤波、内环采样、估算误差都在里面。

建议在已有安全实验条件下，用单关节小幅阶跃或低幅正弦建立实际参考，再在 Gazebo 同条件复现：

- 同时记录命令时间、电机反馈时间、位置速度、接口总力矩、仿真下游 requested/applied torque。
- 区分纯延迟 d 与一阶响应 T；用不同频率的增益和相位辨识，保留另一段数据验证。
- 单独比较支撑、摆动及接触切换；不要仅靠整机闭环互相关拟合电机参数。
- 比较力矩幅值标定、摩擦 / 阻尼、死区、速度反馈带宽、内部采样率及转子等效惯量。

仿真目前是摆腿更理想、力矩反应更快；适度模拟真机执行链路可能改善相似度，但增加延迟也可能使稳定性变差，需要验证。不能直接把 `torque_response_time` 从 4 ms 改成 12 ms 并宣称匹配真机。

## 第三优先级：足地接触与数值收敛

先检查实际 Gazebo 世界、地面 surface 与转换后的机器人 collision 参数；地面和足端共同决定接触行为。

在相同上层指令 / 相同仿真时长下，只改变一类参数：

1. 数值收敛检查：物理步长如 1 ms → 0.5 ms；若实际使用 ODE quick，增加 solver iters。这些是数值误差检查，不是电机或材料辨识。确认 500 / 250 Hz 更新频率与时间基准保持预期。
2. 接触法向：通过静态承重和低速落脚比较压缩量、触地时间、反弹及接触力波形，再调 kp、kd、maxVel、minDepth。数值由实验决定，不给当前日志无法支持的“最佳值”。
3. 切向：确认存在真实滑移后，再通过低速拉动 / 定速测试估计摩擦，调整 mu1/mu2、slip、必要的扭转摩擦。避免用巨大摩擦系数掩盖落脚或姿态问题。
4. 几何：按实物足垫尺寸和变形核对球半径、接触位置和碰撞体。改变 collision 半径也会改变实际触地时刻，应与运动学原点定义一起评估。

ODE 的 kp/kd 与 ERP/CFM 有对应关系，步长和接触参数相互影响，不应同时盲目扫描多个等价参数。官方说明：[物理与接触参数](https://classic.gazebosim.org/tutorials?tut=physics_params)、[摩擦规则](https://get.gazebosim.org/tutorials?cat=physics&tut=friction)。

## 第四优先级：质量、COM、惯量与关节被动力学

总质量应先与实物称重一致，不能通过减轻仿真机器人来掩盖支撑不足。再核对前后 / 左右负载分配、COM 偏移和姿态响应；机身惯量、整机惯量、转子反射惯量应区分。当前 MPC 的固定惯量近似不等同于 Gazebo 各 link 完整动力学。最后根据关节独立测试确定 damping、friction 等值，避免所有关节使用同一个未经辨识的值。

## 保持只改 Gazebo 的实施边界与验收

先冻结真机用的 StateTrotting、MPC、WBC 和控制增益。执行器参数优先放在 Gazebo 专用 `gazebo.yaml` / 仿真 PD 实现；接触参数放在 Gazebo 专用 xacro；物理引擎参数放在明确被启动入口加载的专用 world。

`const.xacro` 的质量 / 惯量 / 运动学常量是共享的；为了只影响仿真，应增加有默认值的仿真 override 或独立生成配置，确认真机展开 URDF 不变。还应明确传给控制器的名义模型是否随 Gazebo 物理模型改变，避免仿真参数和控制器模型一起变化，丢失实验解释性。

顺序：固定站立 → 单关节响应 → 原地踏步 → 前进 / 转弯。每个参数版本在相同初始状态、相同命令、相同步态及相同仿真时间内比较；独立重复采集而不是把同一进程的三个窗口当重复。

验收同时看机身真值误差、估计误差、触地时序、关节响应与力矩，不能只看 RViz 动画。首份统一窗口可作为初始对比参考；真机后段也有高度下降，暂不能把它定义为长期完全稳定的基准。
